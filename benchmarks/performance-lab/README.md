## Autonomous local laboratory

One bounded product operation can now advance every safe action already named
by the coverage report:

```bash
pnpm runtime:run-performance-lab -- \
  --repo /absolute/path/to/product \
  --lab-id product-local-2026-08-12 \
  --max-steps 8 \
  --timeout-ms 30000 \
  --json
```

When the separate verifier rejects the returned finding, repeat with
`--exclude-finding-ids <24-hex-id>[,<24-hex-id>]`. The lab records at most
eight exclusions, returns only the next deterministic eligible candidate, and
completes as `candidate_exclusions_exhausted` when the bounded diagnosis has no
candidate left. An exclusion alone is not verification evidence.

It automatically executes `measure_unmeasured_flow`,
`screen_existing_flow`, `capture_local_browser_flow`, and
`inspect_profile_candidate`. Screening is
limited to safe exact Node/Vitest/Jest tests carrying an explicit benchmark or
software-performance workload signal. Generic tests are never selected. A
visible ranked screen may run from a truncated inventory; once those candidates
are exhausted, the laboratory stops at the truncation boundary. For one
statically qualified Vite flow, browser capture can now resolve the contained
installed Vite module, launch it on the exact loopback origin, attest the

flows may instead use an owned config-disabled development runtime with
environment-file rejection, one static GET warmup, attestation, and cleanup.
Repository-configured Next and production builds are not launched. Other server families,
unverified occupied ports, missing runtimes, and apps requiring custom Vite
configuration stop explicitly. Repository Vite config and automatic
environment-file loading are disabled. It also stops
for source edits, snapshot changes, safety flags, or its step budget. The CLI and
`run_autonomous_performance_lab` MCP operation accept no executable, command,
environment override, URL, or network destination.
